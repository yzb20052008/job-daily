## 二、W5 业务规则治理

### 2.1 变更摘要

| 任务 | 要点 |

| config_code | 默认 | 含义 |
|-------------|------|------|

拨号免费还包含：确认时长（`call_ensure_time`）内同岗已有联系记录 → 免重复扣费。

## 四、W6 体验与稳定性

### 4.1 变更摘要

| 任务 | 要点 |
|------|------|
| W6-1 错误码 | `BizErrorCodes` + `BizException` + `BizExceptionHandler`；返回 `code=业务码`，`message` 中文；移动端仍 toast message |
| W6-2 幂等 | `IdempotentHelper`（Redis SET NX）：报名 `idem:apply:{user}:{post}`、结算 `idem:paySalary:{orderId}`、提现 `idem:withdraw:{userId}` |
| W6-3 任务监控 | `MonitoredJobSupport` 包装 Order/Post/Goods/FinanceRecon；失败写日志 + 可选 Webhook（`job_alert_webhook`） |
| W6-4 异常日志 | api controller 活跃路径去掉 `printStackTrace`，改为 `log.error`；GoodsJob 接通道具过期回写 |

### 4.2 幂等约定

| 接口 | Key | TTL |
|------|-----|-----|
| `POST /api/order/addApply` | `idem:apply:{userId}:{postId}` | 8s |
| `GET /wxPay/miniPaySalary` / `GET /aliPay/appPaySalary` | `idem:paySalary:{orderId}` | 10s |
| `POST /api/finance/withdrawApply` | `idem:withdraw:{userId}` | 5s |

Redis 异常时**降级放行**（避免拖垮主流程），业务侧仍有查库防重/状态幂等。

### 4.3 告警配置

`base_config.job_alert_webhook`：填写企微/钉钉机器人 URL；为空则仅 `log.error`。

### 4.4 验收清单（W6）

- [ ] 连点报名第二次返回「操作过于频繁」或「请勿重复提交」
- [ ] 连点提现/结算短时内被拦截
- [ ] 人为让 OrderJob 抛错时日志有 `[定时任务失败]`；配置 webhook 可收到
- [ ] 业务失败响应 `code` 为业务码（如 90001），移动端仍弹出中文 message
- [ ] api controller 无活跃 `printStackTrace`

## 五、待开工逾期自动取消

| 项 | 说明 |
|----|------|
| 规则 | `order_status=待开工` 且 `end_time < now` → 取消（退积分、释名额、双边通知） |
| 开关 | `base_config.order_no_start_after_end`，`1` 开 / `0` 关（默认开） |
| 入口 | `OrderJob` → `JobOrderServiceImpl.autoFinishOrder` → `autoCancelNoStartAfterEnd` |
| 打卡 | 上班打卡若已过 `end_time` 直接拒绝 |
| 运营台 | 超时异常单计入「待确认超时 + 逾期待开工」 |
| 脚本 | `db/upgrade/V20260829_03_order_no_start_after_end.sql` |
| 历史 | 勿裸 UPDATE；部署后由 OrderJob 幂等清洗 |

验收：

- [ ] 造一笔待开工且 `end_time` 已过，跑 OrderJob 后状态=已取消，双方有通知，积分已退
- [ ] 开关置 `0` 后同类订单不被取消
- [ ] 已过结束时间的待开工单上班打卡失败
- [ ] 运营台超时异常数含逾期待开工
