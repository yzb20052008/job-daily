# 12 版本与变更

## 1. 版本策略建议

| 类型 | 说明 |
|------|------|
| 开源主干 | 持续接收修复与社区贡献 |
| Tag / Release | 对外推荐的可部署里程碑（如 `v1.0.0-oss`） |
| 商业分支（可选） | 客户定制与未开源增强，不强制存在 |

发布 Release 时建议附带：

- 对应 commit  
- 数据库脚本增量列表  
- 破坏性变更（Breaking Changes）  
- 升级步骤

## 4. Changelog 维护约定

建议在每个 GitHub/Gitee Release 使用如下结构：

```markdown
## [vX.Y.Z] - YYYY-MM-DD
### Added
### Changed
### Fixed
### Security
### DB
- 更新 `db/00_job_daily_clean.sql`（或附增量变更说明）
```

社区贡献者提交功能时，可在 PR 中附带 Changelog 草稿，由维护者在发版时合并。
