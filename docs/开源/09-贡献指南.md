# 09 贡献指南

欢迎通过 Issue / Pull Request（或 Gitee Merge Request）参与改进。

---

## 1. 开发流程

1. Fork 或创建分支：`feature/xxx`、`fix/xxx`、`docs/xxx`  
2. 保持与主分支同步，小步提交  
3. 本地验证：后端编译、相关端冒烟  
4. 提交 PR，填写模板化说明  
5. 等待 Review；按意见修改  

---

## 2. 编码约定

| 项 | 要求 |
|----|------|
| 语言 | 业务注释使用中文；对外 API 文档中英均可 |
| Java | 对齐现有 Jeecg / 阿里手册风格；资金与状态变更必须有事务与校验 |
| 前端 | 不随意引入过重新依赖；遵循现有目录 |
| 密钥 | 禁止提交真实密钥、证书、生产库连接 |
| 范围 | 单个 PR 聚焦单一主题，避免无关大重构 |

---

## 3. 提交说明建议

```text
feat(order): 下班打卡回写工时
fix(withdraw): 转账失败同步审核失败态
docs(oss): 补充部署检查清单
```

---

## 4. PR 描述应包含

- 背景与动机  
- 改动摘要（模块级）  
- 测试方式与结果  
- 风险与回滚  
- 是否破坏兼容（API / DB）  
- 若有 SQL：脚本路径与执行顺序  

---

## 5. Issue 分类

| 标签建议 | 用途 |
|----------|------|
| `bug` | 缺陷 |
| `enhancement` | 增强 |
| `documentation` | 文档 |
| `question` | 使用问题 |
| `SECURITY` | 安全（细节勿公开利用） |
| `商务` | 商业合作（非技术需求） |

---

## 6. 行为准则

- 尊重他人，就事论事  
- 不发布恶意代码、挖矿、病毒样本  
- 不在仓库内做商业硬广刷屏  

违反者维护者有权关闭 Issue / 拒绝 PR。

---

## 7. 贡献者权益

贡献在 Apache-2.0 下授权给项目。显著贡献可在发行说明中致谢。
